## Research tracking (research-hub)

This project is tracked by research-hub: `STATUS.md` holds the current state, `experiments/` holds
measurement records, and a hub on the user's PC syncs both to Plane. You never call Plane yourself.

**Before work**
- Read `STATUS.md` (state, current focus, next steps, blockers).
- Read `.research/TASKS.md` if it exists. It lists the open Plane tasks for this project and is
  regenerated by the hub, so don't edit it.

**While working**
- Every benchmark or experiment gets a record: copy `experiments/TEMPLATE.md` to
  `experiments/YYYY-MM-DD-<slug>.md` and fill in setup, exact command, commit, results, conclusion.
  Put real numbers in it, including failed runs.

**After each meaningful unit of work, and before you end a session**, report it:

```bash
python3 .research/report.py \
  --task "QKV optimization" \
  --result "+8.3% throughput (61.7 -> 66.8 tok/s, c6)" \
  --next "test tile=256" \
  --metric tok_s=66.8 --experiment experiments/2026-10-16-qkv-tile.md --label benchmark
```

- `--task` is the Plane work item: its ID (`FURIOSA-12`) if `.research/TASKS.md` shows one, or a
  short title (the hub creates the work item on first use).
- Add `--done` when the task is finished, `--review` when it works but still needs verification
  (parity, repeat runs, a human check), or `--state blocked --blocker "<why>"` when you are stuck.
- Add `--todo "<follow-up>"` (repeatable) for concrete follow-up work; each becomes a Plane task
  under this one. Put loose ideas in STATUS.md Open questions instead.
- Use the metric keys listed at the top of `.research/TASKS.md` for `--metric` whenever they apply,
  so results chart as a time series; add new keys only for genuinely new quantities.
- For a measured run, also pass its configuration as `--param key=value` (tile, batch, concurrency,
  SDK version, ...) and attach result files with `--artifact <path>` (plots, CSV, profile JSON,
  logs; <= 8 MB each). The hub turns every report with metrics/params/artifacts into an MLflow run,
  so runs can be compared and plotted side by side.
- Tag the task with `--label <name>` (repeatable): a work type (`experiment`, `benchmark`, `bug`,
  `analysis`, `docs`, `infra`, `paper`) plus any project label listed at the top of `.research/TASKS.md`.
- On Windows use `python` instead of `python3`.
- The script updates the `STATUS.md` header and log and appends to `.research/events.jsonl`.
  Edit the free-form sections of `STATUS.md` (Findings, Open questions) directly when they change.
- If you commit, include `STATUS.md`, `experiments/` and `.research/events.jsonl` with the related
  code. Don't make commits only for reporting.
